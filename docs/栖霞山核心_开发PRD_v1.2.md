# 栖霞游鉴助手 · 四季伴游开发 PRD

日期：2026-11-01　状态：开发需求基线

产品名称统一为「栖霞游鉴助手」。定位是围绕栖霞山的四季内容与到园服务，帮助游客决定看什么、怎么走、在哪里找到设施。枫况是赏枫期的首要入口，也是当前版本的第一个 Tab；全年内容同时覆盖山林、湖泊、遗迹、茶文化和经核验的地方人文。

本版将四季主题改为按南京时序自动切换，地图上方先展示天地图实际地图，下方提供园区参考图片切换，枫况百分比必须有足够的观测证据。本文定义产品目标与当前数据边界；任何空数据或参考图片都不能被解释为已核验景区点位。

## 1. 依据与本次决策

### 1.1 输入与可信边界

- 原始《枫况｜栖霞山伴游智能体产品需求》v0.6、思维导图及开发 PRD v1.0。
- 园区负责人痛点截图：枫叶之外的吸引力、遗迹与陆羽茶庄、讲解员不足、四季栖霞、信息可靠、停车后找厕所、入口与推广、优惠吸引力、投入合理性。
- 本轮用户要求：真实天地图、厕所和接驳点、首 Tab 枫况、四季主题、枫红百分比、产品名称调整。
- 本轮交互反馈：去掉重复顶部 Tab、按时间自动换季、联动单点有效枫况、枫叶微元素进度、文旅线描图标、轻动效与返回顶部。
- 2026-10-31 下午项目团队现场采风反馈：大部分枫叶仍为绿色，少量微黄；未提供具体点位、观察范围或统计样本，因此只记录定性现象，不换算红度百分比。
- 用户提供的[栖霞山官方季节推文](https://mp.weixin.qq.com/s/xubdcBQ4x4kGIOf8ucr67A)用于理解季节背景；不得作为上述现场采风的点位证据或今年的精确物候预测。

截图是需求访谈记录，不等于公告或核验证据。其中“早上 7 点前免票”“11.12 赏枫季”应进入待核验事项，核对适用日期、人群、入口、审批与来源后才能对游客发布。“文旅一般是国企”不作为所有项目的事实或系统权限依据；本项目按实际运营主体确认采购、数据和预算责任。

### 1.2 当前内容基线

- 2026-10-31 下午采风记录：整体以绿色为主、少量微黄；地点与样本统计范围待补。
- 当前没有达到发布门槛的点位百分比，因此当前枫红进度为未知。未知不等于 0%，也不得按月份、历史推文或未经核验照片推算百分比。
- 当前没有可发布的景点、厕所、停车、接驳站和路线坐标。天地图仅作为基础地理图层；用户提供的插画地图与园区导览图单独查看，不叠加实时坐标点。
- 后续记录至少包含观察日期时间、点位标识、可见范围、叶色统计口径、采集来源、有效期和复核状态。信息不足时只可描述已知定性事实，并明确覆盖范围。

### 1.3 核心决策

1. 全年品牌与导航属于栖霞山，枫况属于秋季强功能；不能用单一枫叶图片与文案替代全年内容。
2. 一级导航依次为「枫况」「地图路线」「问伴游」。首次访问默认打开枫况/季节看点页，顶部只保留品牌，四季时序为非交互指示；所有尺寸均只使用底部主导航。冬春夏不输出虚构的当前枫红状态，而在同一入口先展示当季看点及历史枫况入口。
3. 天地图负责真实地理底图；景区点位、厕所、接驳、停车与路线均由独立结构化数据叠加。底图真实不代表叠加业务数据已核验。
4. 红度百分比是某点位、某观察范围、某时间的人工估计；展示百分比或区间必须同时展示阶段、来源、观察日期与时效，不能冒充全山实时统计。
5. 四季按南京时间自动切换主题与内容，不提供手动季节开关。秋季按有效点位观测联动语义主色；未获得有效红度时显示未知，不拿别处数据或月份推算红度。
6. 先以 H5 完成免登录访问、可用地图与内容闭环。小程序是后续分发形态；本版不得对外宣称已上线小程序。
7. 信息先核验再发布；AI 解释已发布资料，不能生成未核验道路、设施营业状态、票价或史实。

### 3.2 下一阶段 P1

- 经园区核验的非枫叶 POI、遗迹与茶文化短讲解、四季内容编辑和发布日期。
- 真实的停车到厕所连接段、经核验接驳线路、运营日历、站点公告与变更维护。

### 3.3 暂不承诺

界面交互完成不代表内容已经核验或生产服务已经接通。游客端不展示虚构业务记录、测试账号、模拟审计或测试阶段版本标识；生产发布仍须满足第 11 节的数据、授权、运营和现场验收门槛。

## 4. 信息架构与核心流程

### 4.1 页面结构

| 页面/入口 | 内容 | 行为 |
|---|---|---|
| 枫况与季节看点，首 Tab | 自动当前季节、四季时序、分点位红度、阶段图例、来源时效、全年看点 | 选点位可看详情并跳地图；非秋季显示当季看点，枫况可看历史 |
| 地图路线，第二 Tab | 上方天地图实际地图；下方在插画赏秋图/园区导览图间切换；图层、设施列表、同行筛选、路线卡片 | 参考图切换不影响天地图；设施快捷筛选；地图失败可继续浏览列表 |
| 问伴游，第三 Tab | 文字问答、路线/厕所/接驳/景点快捷问句、引用 | 只跳到已发布实体；模型失败有模板回答与原页面入口 |
| 点位详情 | 看什么、短背景、现场观察细节、图片日期、来源、季节标签、设施与路线 | 无审核介绍则显示整理中；不自动补造故事 |
| 路线详情 | 起终点、顺序、核验路径、时间/返程口径、台阶和设施 | 未核验路径不绘为步行导航；未知约束如实说明 |
| 内容后台 | 本版未提供；P1 管理草稿、核验、发布、撤回、纠错 | 生产写入须鉴权与审计 |

品牌按钮回到首 Tab；桌面和移动端共用唯一固定底栏，不再增加顶部 Tab。首次不弹定位或登录；地图和枫况也不要求先聊天。返回列表保留筛选；底部导航与地图控件不互相遮挡。

### 4.2 三条关键流程

1. **赏枫决策**：首 Tab → 查看各点红度/阶段/日期 → 选择看色彩/看成片/看层次 → 点位详情 → 地图/适合同行的路线。
2. **到园服务**：停车出口/站点入口 → 地图已选停车点或接驳点 → 厕所/候车设施列表 → 点位摘要 → 有核验连接段时查看走法；没有时只给位置关系与现场指引。
3. **四季内容发现**：当前季节 → 当季自然/人文/茶文化看点 → 1 分钟短介绍 → 关联短路线或官方活动 → 可选继续问伴游。

## 5. 功能规格

### F01 四季主题与全年内容

默认根据 Asia/Shanghai 日期计算季节：3—5 月春、6—8 月夏、9—11 月秋、12—2 月冬。月份是界面时序规则，不是物候结论；本版按本机时间计算南京日期，每 30 秒检查一次，页面恢复可见时立即校时。跨季自动切换，无需刷新。后续官方物候日历接入须记录来源、周期与版本，不能修改原始观测。

春、夏、秋、冬均有名称、导语、主视觉/中性纹样、主题语义色、内容分类、看点集合和推荐路线。四季时序条只指示当前季节，不承担手动切换。春以苔绿、夏以林绿、秋随观测绿黄红、冬以靛青呈现。非秋季不显示当前红度百分比，秋季演示档案默认收起，展开后保持历史标签，不渲染当季红度。内容为空时显示“当季资料整理中”，不能把秋日照片改标题当春夏冬实景。

| 季节 | 内容方向，需逐项核验 | 视觉语义 |
|---|---|---|
| 春 · 青山初醒 | 山林新绿、湖畔观察、短程人文散步 | 苔绿与纸色；以 moss token 作主题强调 |
| 夏 · 林下清游 | 林荫、湖水、茶文化与遗迹短看点 | 深苔绿、纸色；靛青用于信息收束与页脚 |
| 秋 · 枫色渐浓 | 分点位枫况、颜色层次、倒影、秋日游线 | 枫阶与银杏黄说明；红度仍以记录为准 |
| 冬 · 山静人文 | 山林结构、建筑/遗迹细节、茶事及经核验的活动 | 墨、暖纸与山影；不伪造雪景或冬花信息 |

非枫叶内容至少可按“山林湖泊 / 人文遗迹 / 茶文化 / 到园服务”检索。陆羽茶庄在完成名称、位置、开放信息和内容来源核对前仅作为采集线索，不发布具体历史、营业时间或体验承诺。全年内容遵守原需求的非宗教内容边界；史实、传说、解释分开标识。

验收：四个主题有可见色彩和文案差异；切换后看点随季节变化；秋季枫红记录本身不被切换改写；没有资料时不生成假实景；非秋季无需回秋季也能找到地图、设施与人文内容。

### F01a 时序与数据更新联动

秋季以枫林谷单点有效红度作为主题参考，不对全山简单平均。接口每 5 分钟尝试更新；过期判断每 30 秒执行，失效后停止颜色联动。低值以青绿、中值金黄、高值枫红呈现，颜色变动是视觉表达，不推断黄叶比例或官方最佳观赏期。接口失败保留上次数据但继续判断有效期，未知不转成 0%。

### F01b 动效、加载与返回顶部

- 首次请求显示叶片呼吸与册页骨架，成功后淡出骨架、淡入内容。15 秒超时或连接失败时提供重试，避免加载时误显示“暂无记录”。后台刷新不清空现有内容。
- 页面切换、卡片筛选、详情抽屉、伴游消息与提示使用淡入淡出和小幅位移；图片载入后淡入，册页进入视野后展开。
- 首屏少量低透明度枫叶缓慢漂移，单次叶片进度按序展开；装饰隐藏于读屏且不拦截点击。非秋季也只作为中性/当季配色纹样，不冒充实拍。
- 全站只动 transform/opacity，响应 prefers-reduced-motion，减少动效时内容直接可见。滚动超过 320px 出现返回顶部，按钮与伴游入口、底栏及安全区错开。
- 底栏使用同一线性 SVG 风格：枫叶、楼阁、山水游册；选中枫况为实心枫叶。参考官方小程序的文旅图标类型，不替换或重绘官方品牌标识。

### F02 枫况阶段与百分比进度

红度衡量对象是“该点位记录所描述的可见叶片中已显红的估计占比”，不是单片叶子的成熟度，也不是景区面积或游客拍照评分。后台记录 observationScope、method、observedAt、validUntil、source 与核验人。

数据优先支持红度区间 redPercentMin/redPercentMax；若人工核验给出单一估计值，可存 progressPercent 并标“约”“人工估计”。区间不能在前端静默取中点并当成精确数字。仅发布具备来源和观察范围的有效值；无完整证据时数值为 null。

以一枚大枫叶和十枚小枫叶表达 0—100%：每枚小叶代表 10 个百分点，不足一枚按比例裁切填充；数值越高，填充越多、当前叶色越红。0—50 在苔绿与银杏黄间连续映射，50—100 在银杏黄与枫红间映射；文字使用对应深色 Token。保留百分比、人工估计、图例与可访问文本，不只依赖颜色。视觉旁批仅解释色彩，不替代原记录的人工阶段。推荐阶段为“未明显变色、初红、红绿相间、盛红、落叶阶段、未知”。颜色说明分为“以绿为主、绿黄交错、黄橘渐起、红绿相间、盛红、落叶”，作为人工观察标签，不从红度自动推算黄叶比例。

- 有效记录：显示约 X% 或 X%—Y%、阶段、观测日期、来源与有效期；progressbar 有可访问名称与数值。
- 已过期：显示“历史记录/已过期”和原日期，不进入当前红度推荐；可以展示历史数字但不得称作当前。
- 未知/缺失/看不清：显示“暂无有效百分比”，不绘成 0%，不填充小叶，保留未知旁批。
- 0% 是被明确记录的观测值，不能与缺失混同。
- 落叶阶段不必等于 100%；颜色比例不能代替叶片保有量，密度单独说明。

不默认汇总全山百分比。如未来有加权汇总，必须先明确采样范围、样本量、日期、方法与误差，并另行评审；本版封面可展示某个代表点，必须标点名，或只用文字概述覆盖情况。

验收：卡片与详情都有百分比/区间和进度；数值与 redBand 一致；未知与过期不作为当前 0%；前台长开或跨过截止时间后重新检查时效；绿黄红图例有文字且与季节主题独立。

### F03 天地图真实底图

前端采用 Leaflet 加天地图 WebMercator 矢量底图和地名标注双图层，使用 HTTPS；地图服务的具体服务标识与 API 版本以天地图当前文档与密钥授权为准。展示合法署名和底图自身的标注，不能覆盖或删除服务要求的署名。

配置变量为 `VITE_TIANDITU_KEY`，本地写在 `apps/web/.env.local`，仓库仅提交 `.env.example`。Web 地图 key 会随浏览器请求可见，不应把前端环境变量当作服务端机密保护；生产要在天地图控制台限制应用类型、域名、额度并支持轮换，不把 key 写进日志、截图说明或 PRD。域名和服务类型不匹配导致的鉴权失败必须有可理解的错误提示。

地图初始化以栖霞山核验覆盖区为中心；业务坐标统一使用 `[lng, lat]`、十进制度和明确的 WGS84 来源。渲染到 Leaflet 时按接口约定转换顺序。禁止对已是 WGS84 的点再做 GCJ-02 偏移；来源不明的坐标进入待核验，不混放。上线前在入口、厕所和接驳站实地抽查配准。

提供缩放、回到覆盖区、图层开关和地图/列表联动。地图加载失败、key 未配置、鉴权失败或离线时显示可重试状态，同时保留设施、景点和路线列表；不在失败时无限转圈或清空业务数据。地图按需挂载，离开页面销毁监听和实例，避免重复初始化。

底图仅展示地理位置；本版不以景点之间的直线假装核验步道。没有已核验的接驳站序和线路时不绘制接驳连线；真实折线需要线路来源和核验记录。

### F04 厕所、接驳、停车和休息设施

地图图层至少包含“景点、厕所、接驳站、停车”，默认展示关键设施，游客可独立开关。休息点与座位沿用现有结构，不混同为厕所或接驳设施。图标采用同一套线性 SVG，不能以 emoji 作为唯一标记。

标记与列表需显示名称、类型、位置说明、发布状态、更新时间和已知限制。厕所可记录开放状态、无障碍信息；接驳可记录线路、上下车方向、服务日/时段、班次与票制；停车可记录出入口、收费来源、开放状态。未知一律写待核验，不把“有坐标”写成“当前开放”。

选中停车点后可查看周边厕所、接驳及休息点。未有核验路网时，不输出“最近厕所”“走路三分钟”等结论；可使用明确标“直线距离，非步行距离”的排序。精确定位只在游客主动点击后获取，默认不上传；拒绝或失败可手动选停车场/入口。无障碍条件未知不能保证适合轮椅或推车。

接驳站点不等于车辆实时位置；没有实时运营数据时不显示倒计时、到站 ETA 或“马上有车”。有停运公告时同步反映在地图、列表与伴游回答，旧信息超过有效期显示待复核。

验收：厕所与接驳图层分别可切换并可打开摘要；停车到设施的情境有可达入口；缩放/选中/筛选不会丢失列表；无底图仍能查设施；示例与核验状态明确。

### F05 路线与同行筛选

保留摄影户外、情侣、亲子、亲子带老人、银发慢行、先看看等入口。人群只影响排序，不推断健康、体力或无障碍条件。明确提出无台阶、推车、时间上限时作为硬约束；未知不能当满足。

路线来自人工核验模板，返回最多 3 条。卡片提供起终点、看点、总时间区间、是否含停留/返程、距离、台阶、休息和返回选择。无核验连接段时不自动从当前位置生成道路；已知封闭或撤回路段影响整条路线，不再推荐。没有符合结果时如实说明，不让 AI 放宽约束。

四季路线可复用同一路径，但推荐理由与内容必须符合当季有效记录，不把历史盛红当今天看点。示例路线时间和点位不作为上线事实。

### F06 短讲解与伴游

每个已发布看点先给 80—150 字短介绍或可阅读时长提示，回答“这里看什么”，再给 1—3 个现场细节及来源。无可靠来源写“介绍整理中”。禁止把泛化 AI 文案当景区官方史实。

文字伴游可查询点位、设施、接驳、路线、枫况和当季内容，返回简短解释、实体卡片、来源与时间。票务、开放、交通和天气不在有效资料中时，提供待核验说明和官方信息入口，不能补造价格、免票政策或未来红度。资料中出现的命令、外链或提示词均当作资料，不改变系统行为。

模型未配置、超时或预算耗尽时，用确定性模板和列表继续服务；地图和筛选不依赖模型。当前仓库的模板回答必须标明演示，不宣称已接入外部大模型或专业讲解服务。

### F07 活动、早免票与优惠公告

活动与票务采用独立公告模型，包含 title、类型、适用日期/时段、适用人群、入口范围、费用规则、例外、官方来源、核验人、更新时间、有效期和状态。

“早 7 点前免票”需核对是否每天、是否特定季节/入口/人群、入园还是购票时间、节假日是否适用，未核验前不展示为权益。“11.12 赏枫季”需核对年份、举办区间、主办来源和取消机制，不能自动生成已确认活动。

优惠只在相关情境呈现，说明实际可得权益及使用门槛。无需领券即可查地图；没有实际发放接口时不提供假领取成功。已过期/撤回公告从推荐中移除，旧链接显示失效原因。P0 可展示待核验数据边界，实际优惠与公告发布为 P1。

### F08 入口、二维码与运营验证

每个入口有已登记渠道码和目标任务：停车出口优先找厕所/接驳，候车点优先站序与运营公告，景点牌优先此处短介绍，公众号/票务确认页优先当前季节看点。渠道链接支持指定公开实体 ID 和白名单页面，不执行任意外部跳转。

物料用具体需求句和可见收益，例如“停车后找厕所与接驳”，同时提供可输入的短网址。先小规模试点对比摆放位置和引导语；未证明有效前不大规模投放。线上渠道与线下二维码独立记录，避免把所有访问归给扫码。

P0 为 H5，通过链接/二维码打开；P1 视实际公众号、小程序 AppID、平台资质及域名备案决定是否做小程序容器。小程序内以同样任务入口承接，不重新要求注册才能看地图。

## 6. 设计规范

继续使用 `qixia-autumn-ui`「栖霞秋册」。暖纸底、墨色正文、宋体标题、册页/票根组件和山影页脚贯穿四季；官方 PNG 标识保持原图，不因季节变化重绘。四季通过现有 moss、leaf、ginkgo、indigo 等 token 的语义映射区分，禁止业务样式硬编码新色或自造科技渐变。

阶段色与主题色分开：绿、黄、橘、红是枫况记录的观察标签；页面变为春季主题不会把一个秋季红度条变成“春季红叶”。颜色外同时有文字、日期、图例和有效性说明。

所有图标使用 Lucide 风格内联 SVG；按键有可见 focus、语义名称和至少 44px 触控目标；叶片进度提供 progressbar 语义和可访问文本；只做 transform/opacity 动效并响应 reduced-motion。桌面与 320px 窄屏无横向溢出。地图默认键盘操作可退出，不能让滚轮或焦点锁死整页。

## 7. 数据模型与状态

统一约定：公共 ID 稳定，时间使用带时区的 ISO 8601；API 返回 requestId、dataVersion、generatedAt。经纬度统一顺序、精度和坐标来源。公共图片有作者、拍摄日期、地点与展示许可；历史照片不能冒充当前实景。

| 实体 | 必要字段 | 规则 |
|---|---|---|
| ProductConfig | productName、currentSeasonRule、themeVersion、coverage | 名称为栖霞游鉴助手；主题可配置，当前季节规则可追溯 |
| SeasonTheme | id、name、months、kicker、intro、tokenVariant、contentIds、routeIds、sourceIds | spring/summer/autumn/winter；内容可为空但不能以其他季节实景补齐 |
| Poi | id、name、category、coordinates、crs、subtitle、shortIntro、tags、seasonIds、sourceIds、status | category 至少区分自然、人文遗迹、茶文化；开放状态单独记录 |
| MapleRecord | id、poiId、stage、colorTags、progressPercent 或 redPercentMin/Max、redBand、density、view、observationScope、method、observedAt、validUntil、sourceIds | 缺失为 null；0 是有效观测值；区间与文字一致；时效动态计算 |
| Facility | id、name、kind、coordinates、location、openingStatus、accessibility、note、verifiedAt、sourceIds、validUntil、status | kind=toilet/shuttle/parking/rest/seat；待核验不是开放 |
| ShuttleRoute | id、name、stopIds、geometry、geometryType、operatingCalendar、fare、sourceIds、validUntil、status | geometryType 区分真实核验路线与站序示意；无实时数据不设 ETA |
| Route/Segment | id、stops/segmentIds、geometry、difficulty、stairs、durationRange、returnIncluded、seasonIds、sourceIds、status | 路段连续、连通、可通行且核验后才承诺路线 |
| Knowledge | id、poiId、kind、text、sourceIds、reviewer、status | 事实/传说/解读分开，AI 不自行发布 |
| Notice | id、type、title、rules、startAt、endAt、scope、sourceIds、reviewer、status | 活动、票务、优惠、交通公告；未核验不成为权益 |
| Source/Media | id、type、url 或证据文件、author、capturedAt、license、checkedAt | 公开材料与内部核验证据分权限 |
| Channel | id、placement、targetPage、entityId、activeFrom/To、owner | 只允许白名单目标，用于入口试点 |
| Feedback/Audit | entityId、category、status、operator、at、revision、reason | 纠错可追踪；发布/撤回留审计 |

生产状态流为 draft → verified → published → withdrawn。修改已发布实体生成草稿，不能直接覆盖当前版本。核验与发布有来源、核验人和时间；发布校验依赖完整，失败整体回滚。示例 fixture 使用 demo 标记，不伪装经过该流程。

## 8. 轻量实现与接口

### 8.1 技术选型

| 层 | 选择 | 边界 |
|---|---|---|
| 游客前端 | Vue 3 + Vite + TypeScript；Pinia、Vue Router 沿用 | 移动 H5，地图按需挂载，静态部署 |
| 地图 | Leaflet + 天地图矢量/注记瓦片 + 自有业务覆盖物 | 真实地理底图，核验数据独立；无实时导航 |
| API | Node.js + Hono + TypeScript + Zod | 单服务，确定性筛选与模型 provider 解耦 |
| 数据 | 演示内存 fixture；生产 SQLite + Drizzle | 本轮不把未接入 SQLite 描述为已完成持久化 |
| 发布 | 同域 HTTPS + 单机反向代理；静态前端 + API | 生产配置域名、持久化目录、日志与备份 |

生产前端 API 建议使用同域 `/api/v1`；开发使用 `VITE_API_URL`。天地图 key 仅在部署环境变量中配置且限制域名。外部模型 key 只能放服务端，不能用 VITE 前缀。

### 8.2 接口约定

| 接口 | 主要返回/参数 |
|---|---|
| GET /bootstrap | productName、coverage、地图初始视野/署名、季节规则、seasonThemes、功能开关 |
| GET /map | 覆盖区、POI、facilities、toilets、parking、shuttleStops、shuttleRoutes、legend、disclaimer |
| GET /pois、/pois/:id | 点位、当季标签、简短内容、来源、关联路线与设施 |
| GET /facilities?kind=toilet | 可按 kind 筛选；返回位置、说明与核验状态 |
| GET /maple、/maple/:poiId | 当前/历史记录、百分比或区间、观察范围、时效、来源 |
| GET /routes、/routes/:id | 模板与路段，含时间/返程/约束口径 |
| POST /recommendations/routes | audience、显式 constraints、season；返回匹配原因和不匹配原因 |
| POST /recommendations/maple | interest、audience；只返回有效当前记录 |
| POST /chat | message、上下文；返回回答、公开实体卡片、引用、degraded |
| POST /feedback | category、entityType、entityId、text；返回受理状态，不回显敏感输入 |
| POST /events | 白名单事件、channelId、公开实体、resultCode、匿名会话 ID |

P1 再增加公告查询、渠道管理与管理员写接口。当前 `/admin/summary` 只读监看不能代替生产鉴权、CRUD、审核或审计。

枫况接口字段约定如下。所有业务字段均应来自已发布记录；当前没有满足发布条件的点位记录，因此接口返回空集合，不生成占位枫况：

```json
{
  "poiId": "已发布的景点标识",
  "stage": "经现场核验的观察阶段",
  "progressPercent": null,
  "redBand": null,
  "observationScope": "经核验的观察范围",
  "method": "已记录的人工统计方法",
  "observedAt": "现场观测时间",
  "validUntil": "记录有效截止时间",
  "source": "可追溯的信息来源"
}
```

如发布人工估计值，UI 必须标“约 X% · 人工估计”，不能写“精确实时”。只获得区间时返回区间字段并直接显示区间；未知时数值为 null。服务端和客户端都需按截止时间判定当前有效性，不能只相信永久写死的“有效”字符串。

## 9. 可靠性、性能与运维

- 天地图失败不阻断列表；模型失败不阻断路线/枫况；定位拒绝不阻断手选；图片失败保留文字和来源。
- 不上传精确位置，不采集姓名电话；聊天正文、密钥、照片不进入业务日志。用户主动输入聊天的内容按实际模型处理方式告知。
- 普通 API 建议 p95≤500ms；中端手机常规 4G 首屏入口 3 秒内可操作，地图不阻塞首屏。以上为验收目标，需真实测量，不当作已达成结论。
- 初始 JS 与地图按需加载，图片缩略并懒加载；不一次加载全景区海量覆盖物。
- P1 后台使用独立管理员、HttpOnly/Secure/SameSite Cookie、密码散列、Origin/CSRF 检查、登录与写接口限流；草稿与证据不公开。
- 生产 SQLite 与媒体每日一致性备份，保留策略与恢复责任到人；至少完成一次恢复演练再发布。内存演示数据不承诺重启保存。
- 资料的及时性要靠维护责任：设施/交通有公告即更新；枫况有效期由观测与天气影响配置，默认建议 48 小时并由运营确认；到期从当前推荐剔除。

## 10. 运营、推广与投入评估

### 10.1 入口实验

小规模选停车区、游客中心、接驳候车点、一个人文/自然看点各放一个任务入口，线上选公众号文章或官方服务入口。每个入口登记负责人、位置、文案、目标、投放时间与渠道码。变更物料保留版本，避免无法解释使用变化。

匿名事件建议为 entry_open、season_auto_change、maple_open、maple_to_map、facility_query、shuttle_open、route_open、knowledge_open、notice_open、feedback_submit。字段仅 channelId、公开实体 ID、结果码、dataVersion、会话随机 ID，不记录精确位置、聊天原文、照片或设备指纹。采集失败不影响业务；不把一个人多次刷新当多名游客。

漏斗按“入口打开 → 目标功能打开 → 找到目标/查看路线/阅读内容”分别看转化。二维码没人用时先查是否可见、网络是否通、文案是否对应需求、打开是否快、是否强迫登录，再决定调整位置或停止投放。不得通过假领券或夸张红度诱导扫描。

### 10.2 内容与预算台账

每季更新计划包含内容负责人、需核验的 POI/设施、图片许可、更新频率和待办。旺季优先枫况与到园服务，淡季优先人文/茶文化与适合短游的真实内容；枫叶长期保留历史入口。

投入分为开发、服务器/地图配额/模型、数据采集核验、内容制作、物料投放和维护。每项登记预算/实际金额、依据、责任人、期间、关联交付物；由实际项目主体决定审批规则。先跑低成本试点，再按任务完成、维护工作量和单位有效服务成本决定下一批；不能只用页面访问量声称 ROI。

不预设没有依据的增长或收入目标。首次现场测试建立基线：设施任务完成率、正确找到厕所所需时间、能否解释红度与日期、非秋季看点理解、内容来源辨识、渠道目标动作率、纠错处理时长、过期记录量。每轮给出样本量与局限。
