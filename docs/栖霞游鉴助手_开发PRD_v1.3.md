# 栖霞游鉴助手 · 开发 PRD v1.3

更新日期：2026-11-01。本文为当前开发基线，替代 v1.1 / v1.2 的对应规则；文档版本仅用于研发，不在游客页面展示。

## 1. 产品目标

为来到栖霞山的游客提供可直接使用的枫况、地点查找和游览信息。首个入口是枫况，全年服务同时覆盖自然、人文遗迹、茶文化和到园设施。页面以任务和可操作信息为主，不以宣传叙事、长篇功能介绍占据主要空间。

产品统一名称为“栖霞游鉴助手”。官方图像和官方来源不意味着本项目是官方运营产品。内容区不出现测试版本、模拟业务数据或票务功能。

### 园区问题与对应措施

| 问题 | 本版响应 | 后续需要验证 |
| --- | --- | --- |
| 游客停好车后找不到设施 | 实际地图优先，默认显示六类图层，支持列表检索和距我排序 | 厕所入口、接驳站、停车场实地核对 |
| 只强调红叶，其他季节缺乏使用理由 | 自动四季配色；人文、茶文化、自然入口；折页推荐地点 | 经审核的四季内容与短路线 |
| 缺少讲解员、信息难查询 | 文字伴游依据已发布内容回答，保留来源 | 景点短讲解、音频和问答内容审核 |
| 二维码入口缺少明确价值 | 核心服务无需登录和聊天前置，入口直接指向功能 | 停车出口、游客中心等场景入口试点 |
| 信息可靠性不足 | 区分官方发布、实地观察、地图检索和待核验目录 | 内容负责人、更新机制和纠错处理 |

## 2. 范围与当前状态

本版交付：枫况首页、唯一底部导航、季节侧边栏、实际地图、设施搜索与直线距离、两张参考地图、推荐地点、文字伴游、动效与返回顶部、文档与自动验证。

当前没有已核验的分点位枫况、游览路线或园区业务坐标记录；这些后端集合保持为空。浏览器地图服务检索得到的真实坐标可用于查位置，但不被升级为园区已核验业务记录。推荐地点来源于用户提供的折页，具体运营信息仍待确认。

本版不提供购票、预约支付、实时车辆/车位、到站预测、拥挤度、步行导航、自动叶色识别、复杂行程生成或内容管理后台。反馈暂未保存；问答采用规则与结构化资料，尚未接入大模型。

## 3. 信息架构

| 入口 | 从上到下的内容 | 主要操作 |
| --- | --- | --- |
| 枫况（默认） | 官方红叶进度、采风说明、分点位记录/空态、游览主题 | 查看来源、进入地图、询问枫况 |
| 地图服务 | 实际地图与图层、路线偏好/定位、设施列表、园区参考图、推荐地点 | 图层筛选、定位、查找地点、切换图片、全屏 |
| 问伴游 | 问答内容、输入和快捷问题 | 发送问题、阅读有来源的回答 |
| 右侧四季入口 | 当前时令、恢复自动、四个手动配色选项 | 收起/展开、选色、恢复自动 |

顶部仅保留品牌入口，不重复底部 Tab。地图图片的两个选项卡独立于实际地图；实际地图不加入三选一选项卡。路线偏好保留选项卡形态，不改成下拉选择器。

## 4. 枫况数据与首页

### 4.1 两种记录必须区分

| 属性 | 官方发布 | 实地采风 |
| --- | --- | --- |
| 来源 | 栖霞山官方公众号 | 项目团队现场反馈 |
| 时间 | 2026-10-30 18:13（南京时间） | 2026-10-31 下午 |
| 进度 | 10% | null，不估算百分比 |
| 描述 | 红叶开始转色，大面积红叶尚未到来 | 大部分叶片仍为绿色，少量微黄 |
| 范围 | 官方推文发布进度，非实时监测、非具体点位红叶占比 | 未按具体点位统计，观察范围未细化 |

官方来源：[【枫情预报】红叶已经按捺不住！彩叶上新，活动精彩不断](https://mp.weixin.qq.com/s/xubdcBQ4x4kGIOf8ucr67A)。10% 按该次发布保存，不根据月份、现场文字或过去年度曲线生成新的百分比。采风记录不得补写为 15:00 或其他未提供的精确时刻。

### 4.2 展示与时效

- 首屏优先展示“红叶进度 10%”、官方发布标签、发布日期和来源链接；紧邻展示采风日期与文字说明。
- 用一枚大枫叶和十枚小叶表现进度，每枚小叶对应 10 个百分点；比例越大填充越多，叶色由绿经黄到红。叶色是视觉编码，不推算黄叶比例或最佳观赏日。
- null 与 0% 分开；未知用中性叶片，不能显示为 0%。合法百分比范围为 0—100。
- 秋季且发布后 7 天内显示为近期发布；超过时效、尚未到发布日期或非秋季时明确历史属性。7 天是前端展示规则，不是官方观测有效期。
- 历史快照保留原始数值和日期；非秋季可展开查看。配色切换不重写业务季节或观测数据。
- 分点位记录需要点名、来源、观测时间、范围、方法与有效期。没有资料时展示空态，不复制官方 10% 到各个景点。
- 首次请求使用骨架；15 秒失败后提示重试。后台每 5 分钟刷新，失败保留已有数据；时效每 30 秒及页面恢复时重新检查。

## 5. 四季配色与交互

默认按 Asia/Shanghai 时区的月份自动切换：3—5 月春、6—8 月夏、9—11 月秋、12—2 月冬。月份只决定界面季节，不作为现场物候判断。

| 季节 | 主色 | 页面基调 |
| --- | --- | --- |
| 春 | 苔绿 | 温和浅绿与暖白 |
| 夏 | 林绿 | 清淡绿白，保留纸本质感 |
| 秋 | 枫红 | 暖米纸底，叶色组件独立表达绿黄红 |
| 冬 | 蓝灰 | 浅蓝灰纸底，简洁低饱和 |

右侧“ 四季 ”入口默认收起。展开后可恢复自动或选择四季配色；选择存入 localStorage，刷新后保留。切回自动删除手动值。禁用存储时仍允许本次页面选择。

主题必须覆盖主按钮、底部导航选中态、分组/路线/地图选项卡、边框、界面背景及滚动条。保留叶色进度和服务图标的语义；例如冬季配色不能把官方低红度值绘成高红度。

动效使用透明度及小幅 transform，加载、切页、图片、卡片、对话与返回顶部有一致反馈；尊重 prefers-reduced-motion。枫叶装饰不捕获点击、不占读屏语义。滚动超过 320px 展示返回顶部，与底栏和侧边按钮错开。

## 6. 实际地图

### 6.1 布局与默认图层

实际地图放在地图服务页面上方。景点、厕所、接驳车、停车场、休息点、游客中心六类默认开启，分别显示数量，可独立关闭。路线偏好选项卡、“回到栖霞山”和“使用我的位置”在地图下方。

可搜索地点名称与位置描述；列表点击与地图弹窗联动，地图点支持查看名称、来源、位置描述及距离。重新回到园区时适配已加载地点范围。返回页面时不因推荐地点操作误关其他图层。

### 6.2 坐标来源

- Leaflet 加载天地图 Web Mercator 矢量底图和标注，输入经纬度采用服务返回坐标；保留服务要求的署名。
- 浏览器 Key 通过官方 JS SDK 的 T.LocalSearch 检索，固定栖霞山范围；不直接用浏览器 Key 调用要求服务端权限的 REST 检索接口。
- 地点检索限制并发为 4，按返回名称识别设施类别，筛除范围外、非法坐标及无关商业结果，合并重复地点。
- 用户提供的官方小程序截图录入 23 条名称/位置目录（停车、厕所、景点）。截图中的“距我 xx 米”没有方位，不能反推唯一坐标，也不能作为其他用户的距离。
- 只有目录与检索结果同名对应时才标为“官方目录同名地点”，不写成“官方坐标”。目录未匹配部分可展开查阅，显示待匹配坐标。
- 已发布业务点优先于同名检索点。没有匹配坐标的设施不得使用景区中心或图片像素作为经纬度。接驳车图层表示站点，不代表车辆实时位置。
- 地点加载失败可重试；部分成功保留已有点，零结果明确说明。底图失败与地点失败分别处理，图片和目录仍能使用。

检索关键词和范围是检索条件，不保证外部服务包含全部设施；接驳点、厕所入口等仍需补充园区经纬度和现场核验。

### 6.3 定位与距离

首次打开不申请定位。点击定位后使用浏览器 Geolocation，成功后记录当前坐标、误差和定位时间，在本地按 Haversine 计算点到点球面距离并从近到远排序。小于 1000 米显示 m，其他显示 km，并始终标注“直线距离”。

用户位置仅保存于当前页面内存，不写入项目 API、浏览器持久存储或日志；地点检索参数固定为园区范围。浏览地图本身会向底图服务请求相应视野的瓦片。在园区 5 公里以外时保留园区视野，避免地图跳远导致地标不可见。

权限拒绝、不支持、超时和失败均给出可恢复说明；不回退到虚构位置。更新位置重新计算距离，不宣称连续实时追踪。距离不代替步行路线、坡度或台阶信息。

## 7. 园区图片与推荐地点

### 7.1 参考图片

实际地图下方提供“插画赏秋图”和“园区导览图”两个选项卡。资产分别为 qixia-illustrated.png / qixia-guide.png，来自用户提供图片。切换参考图不隐藏实际地图或重置设施筛选。

两图均支持放大查看、1—5 倍缩放、拖动、复位、全屏与关闭。全屏优先请求横屏，设备不支持方向锁时使用横向展示回退；不支持全屏时保留页内查看。支持键盘关闭及焦点返回。

图片未与坐标配准，不能把图中路线当导航。图面设施、开放及运营信息需按园区当日情况确认。

## 8. 伴游与内容边界

本版通过结构化数据和规则问答回应枫况、设施及路线问题。枫况回答同时说明官方发布时间、10% 的口径和 10 月 31 日采风，不声称其为实时或点位统计。

设施问题引导使用实际地图与目录，缺少已核验路线时说明无可发布路线。不得生成具体的未核验班次、经营时间、门票、活动承诺或历史故事。非秋季内容不伪装为当季实拍。未来大模型接入也必须遵循相同数据来源要求。

## 9. 轻量技术方案与数据契约

前端 Vue 3 / Vite / TypeScript，Lucide 与少量自定义线性 SVG，CSS 语义 Token 管理四季；地图使用 Leaflet，地点检索按需加载官方浏览器 SDK。后端 Node.js / Hono / TypeScript / Zod 单服务，不引入微服务或消息队列。本版发布内容在代码中维护，无数据库。

| 对象 | 关键字段与规则 |
| --- | --- |
| 官方快照 | publishedAt、progressPercent、source、reference、scope；不与点位记录混用 |
| 采风记录 | observationPeriod、summary、source、scope、progressPercent:null |
| 地图检索点 | id、name、kind、coordinates:[lng,lat]、location、source、officialName? |
| 官方目录 | name、kind、location、aliases；没有坐标字段时不标点 |
| 用户定位 | coordinates、accuracy、at；仅内存 |
| 分点位枫况 | poiId、progressPercent/null、stage、redBand、observedAt、validUntil、source |
| 业务设施/路线 | 仅接受经核验发布的记录；未接入时数组为空 |

统一 API 前缀 /api/v1，成功返回 {data, meta}，meta 只含请求 ID 和生成时间。GET /bootstrap、/foliage-context、/map、/pois、/maple、/routes、/facilities 与对应详情；POST /recommendations/routes、/recommendations/maple、/chat。POST /feedback 未接入保存，返回 503，不显示保存成功。

配置通过 VITE_API_URL、VITE_TIANDITU_KEY 提供，真实环境文件不得提交。浏览器 Key 可见于打包结果，部署需配置域名限制；定位部署需 HTTPS。本版无身份系统，后续持久化写入上线前另补鉴权、存储与审计。

## 10. 验收条件

1. 打开首页即见官方 10%、2026-10-30 来源以及独立的 10 月 31 日下午采风；没有虚构点位占比。
2. 南京月份跨界正确；手动春/夏/秋/冬能同时改变背景、按钮、选项卡、滚动条；刷新保留，恢复自动后按真实日期。
3. 实际地图置顶、六图层默认开启；成功检索点显示在地图与列表，查找、筛选和回到园区可用。
4. 有定位时显示本次定位的直线距离与误差，未定位不沿用截图距离；拒绝/超时仍可查名称与参考图。
5. 两图独立切换、放大、复位、拖动和关闭可用；全屏横屏有设备兼容回退。
6. 推荐地点位置正确；同名景点可跳转，未取得坐标时如实提示；页面业务文案称实际地图，服务署名保留。
7. 320px 窄屏无横向页面溢出；底栏不重复，选项卡可滚动，侧边栏及底栏不挡关键操作。
8. pnpm typecheck、pnpm test、pnpm build、git diff --check 通过，浏览器核验结果记录于验证文档。

## 12. 本次交付验证

2026-11-01：类型检查、16 项自动测试、前后端生产构建通过。浏览器确认首页官方 10% 与独立采风说明、四季配色联动、手动选择刷新保留及恢复自动；实际地图检索已成功返回地点，六类图层默认开启，参考图和推荐地点位于其下方。
