# 栖霞山核心 · 四季伴游

面向移动 H5 的栖霞山轻量伴游项目。默认首屏与首个 Tab 为**枫况**，同时提供四季主题、天地图设施查找、路线与文字伴游。产品围绕“看山、读山、安心游山”展开，覆盖自然景观、文化遗迹和茶文化，不局限于赏枫。

开发需求与负责人痛点的对应方案见 [开发 PRD v1.1](docs/栖霞山核心_开发PRD_v1.1.md)。PRD 中标记为后续阶段的审核后台、专业讲解、官方票务及运营功能，不等同于本版已实现。

> 当前为可运行的演示版本。**真实地图底图与演示业务点位分开处理**：天地图提供真实底图，景点、厕所、停车场、接驳站、线路、枫红百分比均是演示数据，尚未经过园区现场核验。不可用作现场导航或实时运营信息。

## 技术栈

- 前端：Vue 3、Vite、TypeScript、Lucide Vue，Leaflet 加载天地图瓦片
- 后端：Node.js、Hono、TypeScript、Zod
- 数据：内存 fixtures；后续可接入 SQLite + Drizzle，无需引入重型服务
- UI：`qixia-autumn-ui`「栖霞秋册」，暖纸底、宋体标题、册页卡、靛青山影页脚；四季通过设计 Token 切换

## 本地运行

要求 Node.js 20+、pnpm 9+。

```bash
pnpm install
```

将 `apps/web/.env.example` 复制为 `apps/web/.env.local`，填写天地图浏览器端 Key：

```dotenv
VITE_API_URL=http://localhost:8787/api/v1
VITE_TIANDITU_KEY=你的天地图浏览器端Key
```

```bash
pnpm dev
```

前端为 `http://localhost:5173/`，API 为 `http://localhost:8787/api/v1`。更改环境变量后需重启 Vite；生产构建前也需配置对应的 `VITE_` 变量。

### 天地图配置

使用天地图影像/矢量服务的浏览器端授权 Key，允许本地测试域名和正式部署域名访问。地图通过 HTTPS 访问天地图矢量底图与中文注记服务，保留服务归属。根据账号授权设置与服务限制，域名、额度或 Key 类型不匹配时可能无法加载底图。

`VITE_` 变量会进入浏览器构建产物，浏览器端地图 Key 应配置域名限制；它不适合作为服务端秘密。真实 Key 仅保存在本机被 Git 忽略的 `.env.local`，仓库示例不含真实 Key。

没有配置 Key 或地图服务不可用时，页面保留设施列表与重试入口。坐标采用 `[经度, 纬度]`，地图组件传给 Leaflet 时转换为 `[纬度, 经度]`，不要直接混用 GCJ-02 坐标。接驳线路仅表达演示站点关系，不表示可行驶道路、班次或车辆实时位置。

## 已实现

- “枫况 / 地图与服务 / 文字伴游”导航，移动端简写为“枫况 / 地图服务 / 问伴游”，默认进入枫况
- 春、夏、秋、冬四种主题，按上海时区的月份默认选择，可手动预览并回到当前季节；主题切换不改变观测数据
- 分点枫况：红叶进度数字与进度条、红度区间、密度、视角、观察时间、来源和有效期
- 枫况百分比为样例观测值；绿色、黄色、红色阶段用于理解物候，不是全山实时统计
- 四季文化与游览内容入口：遗迹、茶文化、山林等
- 天地图真实底图、中文注记，厕所、接驳站、停车场和景观点位标记及分类筛选；支持定位与恢复栖霞山视野
- 设施列表与点位详情；地图加载失败时仍可浏览结构化信息
- 游客同行类型筛选路线、路线详情抽屉、时间与设施提示
- 文字伴游确定性降级回答；无需外部模型 Key 即可运行
- 最小内容监看页面、纠错和事件演示接口
- 移动布局、键盘焦点与减少动画偏好支持

枫红百分比指**单个观察点中红叶占比的演示估计**，不能跨点位简单平均为全山红度。缺测值保持未知，过期值不作为当前推荐依据。设施尚无车位余量、排队时长或接驳班次实时数据。

## API 与验证

API 前缀为 `/api/v1`，主要接口：

| 接口 | 用途 |
| --- | --- |
| `GET /bootstrap` | 品牌、季节主题和功能配置 |
| `GET /map` | 地图中心、设施、接驳站与演示线路 |
| `GET /facilities?kind=toilet` | 设施筛选，支持 `parking / toilet / shuttle / rest / seat` |
| `GET /pois`、`GET /pois/:id` | 景点与关联信息 |
| `GET /routes`、`GET /routes/:id` | 路线模板 |
| `GET /maple`、`GET /maple/:poiId` | 枫况与进度百分比 |
| `POST /recommendations/routes`、`POST /recommendations/maple` | 条件推荐 |
| `POST /chat` | 结构化数据的文字伴游降级回答 |
| `POST /feedback`、`POST /events` | 演示接收接口，不做持久化 |

成功响应包含 `data` 和 `meta.requestId / dataVersion / generatedAt`。模型接入后，模型密钥只能配置在服务端。本版内容后台仅监看，不提供正式审核、权限或编辑功能。

```bash
pnpm typecheck
pnpm test
pnpm build
```

本版工程与浏览器检查结果见 [验证记录 v0.2](docs/验证记录_v0.2.md)。

## 素材来源

官方栖霞山标识、山影纹样、设计 Token 来自 `qixia-autumn-ui`。景点配图来自用户提供的 `枫客松文档资料/枫叶素材_队友共享版`，按素材描述选择秋林、湖面、山门和红叶坡图片。配图是展示素材，不是实时拍摄；正式发布前由项目方确认许可与图文对应关系。

## 上线前需要完成

1. 园区核验并替换景点、设施坐标、道路、开放状态及接驳信息；真实道路才能用于导航。
2. 建立内容来源、观测方法、有效期、复核、撤回与纠错闭环，落实专业文化讲解审核。
3. 接入 SQLite、持久化反馈、管理员会话与审计；当前 CORS 和演示接口不应直接用于生产后台。
4. 对接官方入口、票务与政策来源；“11.12 赏枫季”“7 点前免票”等访谈线索须经确认，不能直接承诺。
5. 按 PRD 分阶段验证入口使用率、设施查找成功率、内容阅读与成本，再决定扩大功能与推广投入。
